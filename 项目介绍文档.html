一、项目背景与目标

定位：一个可直接用于生产环境的浏览器性能监控 SDK，以单个 JS 文件形式通过 <script> 标签引入。

目标：

  • 采集 Core Web Vitals 三大指标（LCP / FID / CLS）
  • 监控 JS 运行时错误、资源加载错误、Promise 未捕获异常
  • 可靠的批量上报链路，覆盖弱网、离线、页面关闭等极端场景
  • 零依赖打包，window.PerfMonitor.init({...}) 一行启动

三、核心模块详解

3.1 性能指标采集 (metrics.ts)

指标PerformanceObserver type关键处理
LCPlargest-contentful-paintbuffered:true 防漏采；取 renderTime 非 loadTime
FIDfirst-input无需 buffered；try/catch 降级到 getEntriesByType
CLSlayout-shiftbuffered:true；过滤 hadRecentInput；闭包累加 value

3.2 错误监控 (error.ts)

错误类型API关键技术点
JS 运行时window 'error' + captureevent instanceof ErrorEvent 区分
资源加载同上资源错误不冒泡，必须 {capture:true}；从 event.target.tagName 提取信息
Promiseunhandledrejectionreason instanceof Error 分支处理

⚠️ 踩坑：资源错误监听中 event 参数被 TS 推断为 ErrorEvent，instanceof ErrorEvent 守卫后 TS 收窄为 never。修复：手动标注 event: Event。

3.3 批量队列 (queue.ts)

设计：生产者-消费者模式。采集层只管 addToQueue()，不关心如何发送。

  • 双触发条件：queue.length >= batchSize 或 setInterval 定时器到期
  • flush() 先 [...queue] 快照再 queue.length=0 清空，防止异步回调数据污染
  • 回调注入：onFlush(sender.send) 解耦队列与发送器
  • drainQueue()：供 pagehide 使用，只快照不清回调

3.4 双通道发送器 (sender.ts)

状态机设计：

send(items)
  ├─ 去重过滤
  ├─ fetch(keepalive)
  │    ├─ 成功 → replayStaleData(DB补发) → clearDB
  │    └─ 失败 → 重试(1s间隔, 最多3次)
  │              └─ 全失败 → saveToDB → sendBeacon

为什么双通道：fetch 可判断 HTTP 状态码、支持重试，但页面关闭时可能中断。sendBeacon 不返回结果但卸载时更可靠——两者互补。

3.5 IndexedDB 离线队列 (storage.ts)

设计决策：

  • 批量存：一个 flush 批次 = 一条 DB 记录（含 items 数组），减少事务开销
  • 单例缓存：openDB() 缓存 IDBDatabase 实例，避免重复连接
  • Promise 封装：所有事件回调转为 async/await 风格
  • resolve 时机：在 tx.oncomplete 而非 add.onsuccess——保证事务真正提交
  • 扁平化返回：loadAllFromDB() 将所有记录的 items 合并为一个数组

五、工程难点：页面卸载时数据丢失

架构级问题 这是项目开发中遇到的最具挑战性的技术卡点。

5.1 问题描述

用户关闭标签页后，队列中未发送的监控数据永久丢失。IndexedDB 无残留，控制台无异常。

5.2 根因

旧设计中 pagehide 走完整 sender 异步流程：fetch → 失败 → setTimeout 1s → retry × 3 → saveToDB。但浏览器在 pagehide 后立即开始销毁进程，异步操作被取消，saveToDB 永远执行不到。

5.3 解决方案：双路径分流

// 改造前：所有场景走同一条路径
setupUnload(flush)  // flush → sender.send() [async + retry]

// 改造后：场景分流
setupUnload(
    flush,                                    // visibilitychange → 正常路径
    () => {                                   // pagehide → 快速通道
        const snapshot = drainQueue();
        saveToDB(snapshot);                   // 立即写 IndexedDB
        navigator.sendBeacon(url, body);      // 最后尝试发送
    }
);

5.4 涉及的关键概念

  • 浏览器页面生命周期：visibilitychange vs pagehide 的触发顺序
  • 异步竞态条件：setTimeout / Promise 在页面销毁时被取消
  • keepalive 的局限性：只保单个请求，不保重试链
  • IndexedDB 事务在 pagehide 中的特殊待遇
  • sendBeacon 的 W3C 设计意图——就是为这个场景设计的

六、TypeScript 类型设计

判别联合类型（Discriminated Union）：

type MetricData = { type: 'LCP'|'FID'|'CLS'; value: number; ... }
type ErrorData  = { type: 'jsError'|'resourceError'|'promiseError'; message: string; ... }
type TransportItem = MetricData | ErrorData  // 队列统一类型

类型守卫：

function isError(item: TransportItem): item is ErrorData { ... }
function isMetric(item: TransportItem): item is MetricData { ... }

泛型版本（规划中）：isItemType<T, S>(item, types): item is Extract<T, {type: S[number]}>
